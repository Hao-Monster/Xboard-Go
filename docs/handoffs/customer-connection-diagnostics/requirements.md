# Go 客户连接诊断需求书

本文件的 CC-01–CC-18 是交接追踪标签，待 D0 映射至真实治理编号。状态统一为 **需求/设计交接；Go 实现与验收 NOT RUN**。详细机制见 [design.md](design.md)，逐项测试见 [test-matrix.md](test-matrix.md)。

## 1. 业务目标与第一版范围

管理员不再手动把订阅 token 转成 UUID、逐台 SSH 搜日志。输入完整订单号，系统解析实际使用订阅的客户，按客户、节点、时间和目标展示节点真实观察到的连接、DNS、拒绝、路由/拨号失败及节点内调用链。需要时为该客户开启十五分钟详细诊断；任何日志故障不得改变代理放行、设备限制、计费或撤权行为。

角色：第一版仅已认证管理员。分销商购买者不是日志归属主体；实际 subscriber 才是客户。已有客户日志 ID 是查询条件，不是授权凭证。持有订单号或 trace ID也不构成查询权限。

覆盖：共享 Xboard-Node 中 sing-box 实际启用协议的 TCP、UDP 和多路复用逻辑流。Xray 观测、客户端本地 DNS/路由、应用内部 HTTP 状态均不在首期。节点没看到的请求不能被 UI解释为“没有访问”或“网站正常”。

## 3. 用户流程及失败分支

### 3.1 从订单定位客户

1. 管理员进入日志中心，输入完整订单号或从现有订单带入 order_id。
2. 后端认证管理员、验证恰好一种输入；只读业务库解析订单和实际subscriber。
3. 展示最小身份卡：order_id、完整trade_no、订单状态/类型、客户展示名、订阅名称、客户日志ID。不得返回UUID、token、订阅URL。
4. scope未初始化时提示“客户连接诊断尚未初始化”，仅有权限的显式动作能初始化；禁止临时scope或回退UUID。
5. 缺订单、缺subscriber、非法输入分别显示具体错误，清空旧客户数据，不能保留旧客户结果造成误认。

### 3.2 查询与连接详情

1. 默认查询最近15分钟，可调整至72小时以内，选择节点/域名模式/错误/trace。
2. 返回连接目标摘要和coverage；即使空列表也显示覆盖状态和查询限制。
3. 展开某连接得到按seq排序的事件、真实span树/耗时、DNS关联和栈来源。DNS只能沿本客户事件已有的授权操作ID展开。
4. 长连接跨窗口显示“开始记录不在当前窗口”；缺父span、未观察结束、无栈都独立标识。
5. 游标过期、后端故障、读取/返回预算耗尽、来源不完整给明确状态；不把失败转成空成功。刷新建立新快照纳入晚到日志。

### 3.3 十五分钟详细诊断

1. 仅订单模式显示可操作按钮；提交start时校验存储ready、用户当前节点资格和并发上限。
2. 立即返回pending及原截止时间，显示支持/不支持/离线/已确认的节点数量；ACK部分到达显示partial。
3. 页面离开不会隐式stop；显示“停止诊断”并等待逐节点确认；离线节点标“最晚按原租约到期”。
4. 重复点击或请求重试不延长截止。到期后baseline继续，detail及异常栈停止；长连接与共享DNS同样受限。
5. 控制面/存储故障显示失败或unknown，不能伪装成功；原有代理、订单和订阅功能继续原行为。

### 3.4 仅有客户日志ID

输入24位小写hex ID后可只读query/详情，服务端固定当前scope。标“未绑定订单”，不能反查哈希、猜客户资料、开启/停止租约或猜全节点资格；无法确定覆盖范围时unknown。切回订单模式清除旧请求、trace、分页和状态。

## 4. 必须保持的字段含义

| 字段/展示 | 含义与禁止的误解 |
| --- | --- |
| order_id / trade_no | 解析客户的业务入口；不是trace、日志授权或采集身份 |
| diagnostic_id | 稳定客户标识；不是UUID哈希，不是凭据 |
| panel_scope | 安装身份；不由域名、密钥、版本或当前UUID推导 |
| connection_id / trace_id | connection类的一次逻辑代理流；二者相等；不等于外层QUIC连接 |
| runtime_id | 当前节点进程实例，重启变化 |
| selected_target_address / socket_peer | 逻辑目标与实际socket对端可以不同，不能把上游代理IP说成目标站IP |
| observed_domain / domain_source | 实际可见域名及request/sniff/dns/unknown来源；不据IP反猜为已知域名 |
| node_resolution | resolved/cache_hit/failed/not_performed；客户端DNS仍可能unknown |
| has_error / error_stages | 累计失败事实；后续成功不覆盖历史失败 |
| span_status | 节点内操作结果；不表示网站或App整体正常 |
| coverage | 当前范围的可验证观测覆盖；不表示客户访问事实或网站健康 |
| stack_capture_kind | 真实捕获来源；边界栈不是底层创建栈 |

## 5. 首期非目标与后续范围

首期不采集HTTP正文、帖子、请求完整URL/headers、密码、token、UUID、邮箱、客户源IP/设备载荷；不开放分销商自助跨租户查询；不做客户端改造、Xray观测、逐包日志、网站成功判定、未记录历史补造、长期日志备份、永久双写、完整OTel/Jaeger平台。

首期单个受信任查询端点，配置storage_generation与稳定身份；旧/新库双源查询和实际主机迁移属于后续D7.3/P2。可以交付迁移手册，但不为本轮预先建设完整双源系统。正式接替PHP是单独数据/控制权迁入工作，见详细设计的决策A与迁移步骤。

## 6. 首期完成定义

CC-01–CC-18有实现与逐项证据；两个合成客户不会串日志，真实TCP/UDP/DNS成功/失败可从订单定位，租约准确到期/停止且旧ACK不覆盖新会话，库/采集故障不改变代理和计费，查询/栈/队列符合预算，管理员页面真实浏览器可用，性能和固定候选身份有原始报告。现场24–48h与实际用户业务验收须独立记录，未执行时明确NOT RUN。
