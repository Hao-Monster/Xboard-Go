状态：设计交接，所有Go业务任务待开发/待裁决；没有已授权的服务器动作。D标签是本包局部任务，不是已注册Work Item。先看[README](README.md)的责任和A–D决策，再按本表实施。与PHP共享节点的协作只通过冻结协议/候选；Go接手者不并发修改Node仓库。

## 1. 开工与治理

接手者先执行只读核对：`git status --short --branch`、`git branch -vv`、`git worktree list`，阅读适用AGENTS与现有diff。远端工作前正常fetch并核对PR/CI；保持唯一开发分支和单写者，不重置或清理其他worktree。纯设计交接不要求伪造治理编号；实施前将CC需求映射到真实`docs/project/requirements.json`、work-items/decisions/risks等，核对Issue与M0–M4 Milestone。不得重开旧OBS-001或拿其运维日志进度充作客户诊断完成。

本包不创建Issue/PR或改变JSON/STATUS；开发人员取得对应阶段授权后登记，JSON变动才运行`go run ./cmd/projectctl generate`与`go run ./cmd/projectctl check`，生成STATUS不可手改。当前源码/文档基线是本地快照，不等同当前远端/生产。

## 4. 测试执行与证据策略

先把测试用例写出来，再实现；bug先有原版复现，修复后复跑原用例及相邻负面对照。测试命令以当前仓库go.mod/package.json/工作流为准，最小验证后按影响面扩大，最终候选做一次适用完整检查，不因文档或小改动反复跑全套。

- Go：相关包`go test`和`go vet`；涉及公共/运行时路径时扩大到`go test ./...`、`go vet ./...`、`go build ./...`。并发/owner/Redis/租约必须有Linux race。0个匹配测试或全SKIP不是PASS。
- Web：typecheck、lint、相关组件/交互测试；公共组件/依赖改变或最终候选按规则执行全suite/build；桌面/窄屏真实浏览器覆盖关键流程。
- 采集/库/guard：真实隔离Linux journald、固定Vector/vmauth/VL，不用Python单测或Mock替代真实配置/权限/挂载/重启验证。测试凭据合成且不进入仓库。
- Node：由共享节点负责人提交真实服务路径/控制时序回归、适用完整internal/race/vet/gofmt/govulncheck、Linux amd64/arm64及镜像/校验资料；Go开发者核对兼容输入，不复写或私自构建替换共享Node。
- 性能：原基线/baseline/detail同环境同负载，报告样本、持续时间、吞吐、连接P95、CPU/内存/queue、失败负载与抓栈成本，原始输出留存。

证据目录由实施任务选择受控的忽略/制品位置；不要把真实日志、生产数据或secret放进Git。报告每条测试标签、命令、匹配数、环境、源码SHA/脏diff身份、PASS/FAIL/NOT RUN与原因、原始文件摘要。没有证据路径的“已测试”不计完成。

## 5. 发布准备与接续边界

开发测试和生产发布按Go现有不同CI/CD路径准备；`observability.yml`只是现有运维验证，不能当客户诊断部署入口。先核对触发器、environment、权限、目标、不可变artifact和回滚。需要新入口时只做方案/可审查变更，取得对应授权后实施；禁止本地SSH/SCP发布、容器切换、服务重启或远程格式化。

正式节点协议逐步发布：面板先兼容旧节点，节点未支持显示unsupported；新节点连旧面板保持原业务。故障先停detail/控制新租约、保留数据与证据；节点/面板按固定旧制品与原CI流程回滚，不删除scope/卷、不放开设备限制或计费、不恢复过期Redis租约。
