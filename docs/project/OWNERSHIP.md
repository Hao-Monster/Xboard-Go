# 责任与并发集成

项目当前由单一维护者负责最终集成，不启用会要求维护者自我审批的 CODEOWNERS 门禁。所有权通过工作项和集成通道表达。

## 集成责任

- 每个 Issue 只有一个集成责任人，即使调查、测试和安全审查可以并行。
- 并行任务不得同时修改共享治理文件、数据库迁移序列、公共 API 契约或同一前端路由；需要时由集成责任人先冻结接口。
- `docs/project/*.json`、`docs/project/STATUS.md`、`go.mod`、锁文件、CI、迁移目录和路由入口属于共享集成面。
- 子任务交付的是独立 commit/PR 和验证证据，最终责任人负责重放测试、消解冲突和更新状态。

## 并发拆分边界

优先按领域和证据类型拆分：只读取证、测试缺口、安全审查、迁移演练可以并行；会改变同一业务不变量或共享数据模型的实现必须串行集成。
