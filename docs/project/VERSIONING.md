# 版本与发布策略

项目采用语义化版本。`0.x` 表示仍可能发生不兼容变化；任何 `alpha`/`beta`/`rc` 都是非生产候选。

## 版本通道

- `v0.1.0-alpha.0`：M0 治理基线，首个可追溯非生产快照。
- 后续 `alpha.N`：功能或迁移里程碑尚未完成。
- `beta.N`：80 个需求范围已关闭，仍在迁移、性能和安全验收。
- `rc.N`：M3 退出条件满足，等待生产准备决策。
- `v1.0.0`：只有 M4 全部满足并另获生产授权后考虑。

## 创建规则

1. Tag 必须指向已合并到 `main` 的精确提交。
2. 该提交的所有必需 CI/CodeQL/治理检查必须成功。
3. Release notes 必须列出需求/工作项、迁移、已知风险、验证提交和回滚方式。
4. 使用 annotated Tag；禁止移动或复用已发布 Tag。
5. 未满足门禁时不以“测试版”名义绕过，保持 `Unreleased` 并记录阻塞。
