1. 每次开始工作先读取 JSON 台账，确定 AUD18 编号、候选 SHA、现有工作项、Issue 和里程碑。
2. 每项按 scope / implementation / verification / migration / acceptance 分别记录，不用一个“完成”覆盖全部。
3. 完成后在该项 history 追加日期、实际提交、PR、测试命令或 CI URL、结果、遗留项；不得仅替换旧 SHA 将历史测试升级成当前证据。
4. 只有该项 completion_criteria 均有同一目标版本的可核验证据时才关闭；不适用项需注明理由。
5. 同步必要的既有工作项/需求/风险；运行 projectctl generate 和 check。新增台账目前需单独 JSON 完整性校验，projectctl 尚未自动校验其扩展字段。
6. GitHub Issue 的关闭/重开、推送、合并和部署按授权处理；本轮不执行这些操作。
7. 新问题挂到对应编号下；确需独立任务则追加编号，不重排 01-18。
